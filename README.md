## 2. 一帧处理流程

按实际执行顺序简述 `onFrame`：

1.调用 checkFrame 做五项校验：帧号严格递增、时间戳严格递增、编号非负、同帧编号不重复、类型与已创建目标一致；
2.任一项失败 → 构造 accepted=false 的结果返回，不修改任何目标，也不推进帧号与时间戳基准；
3.校验通过后才计算帧间隔 dt = (本帧时间戳 − 上一成功帧时间戳) / 1e9（首帧为 0）；
4.第一遍遍历本帧观测：已存在的目标调用 updateObserved，未创建过的编号按类型 new 一个新目标；
5.第二遍遍历所有目标：本帧未被观测且在 TRACK 的目标调用updateUnobserved，累加丢失帧数，达到阈值转入 LOST 并清零；
6.更新 last_frame_id_ 与 last_timestamp_ns_；
7.构造 Result：逐个调用 snapshot() 生成快照，统计 TRACK / LOST 数量与两类装甲数量。

重点说明：整帧校验失败时，为什么不会留下部分修改。
